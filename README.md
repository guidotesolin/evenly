# Evenly

Household expenses for two (or more): each person's monthly fixed costs with a reference dollar,
plus a Tricount-style shared list that splits evenly and settles up. Android app built with
React Native + Expo on Supabase. UI in Spanish.

Design and reasoning: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Task board:
[docs/TASKS.md](docs/TASKS.md).

## Setup

Requirements: Node 24 (`.nvmrc`), Docker (for the local Supabase stack), and for running on a
phone:

- JDK 17 (`sudo apt install openjdk-17-jdk`). It can live next to a newer default Java: Gradle
  reads `JAVA_HOME`, not the `java` on the `PATH`.
- Android Studio, only for its SDK manager: SDK Platform 37 and Build-Tools 37.0.0 (the versions
  React Native 0.88 compiles with; check `node_modules/react-native/gradle/libs.versions.toml`
  after an upgrade).
- In `~/.bashrc`, then open a new terminal:

  ```bash
  export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
  export ANDROID_HOME=$HOME/Android/Sdk
  export PATH=$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator
  ```

```bash
npm ci
cp .env.example .env
git config core.hooksPath .githooks
```

The pre-commit hook rejects env files and, when [gitleaks](https://github.com/gitleaks/gitleaks)
is installed, scans staged content for secrets.

## Development

The app uses native modules, so it runs in a **development build** installed on the phone, not in
Expo Go. The build holds the native code; the JavaScript comes live from Metro on this machine.

### Connecting the phone (wireless debugging)

Works on Android 11+ with the phone and the machine on the same network; no USB cable needed.

1. Phone: Settings → About phone → tap **Build number** seven times. Then in **Developer options**
   turn on **Wireless debugging**. On Xiaomi also turn on **Install via USB**: it gates every
   `adb` install, wireless included.
2. **Pair, once per machine.** In Wireless debugging tap **Pair device with pairing code**. The
   dialog shows a 6-digit code and an IP:port **used only for pairing**. Keep it open and run:

   ```bash
   adb pair 192.168.x.x:PAIRING_PORT CODE
   ```

3. **Connect, every session.** The Wireless debugging screen shows **IP address & port**, a
   different port that changes whenever wireless debugging or the phone restarts:

   ```bash
   adb connect 192.168.x.x:PORT
   adb devices    # the phone must say "device"
   ```

   If it is listed twice (the manual connection and an `_adb-tls-connect` one found on the
   network), `adb disconnect` the manual one; the other survives port changes.

### Daily loop

```bash
set -a; . ./.env; set +a; npx supabase start   # local backend, with the Google client ID
adb devices                                    # phone connected? otherwise adb connect
npm start                                      # Metro; press `a` to open the app on the phone
```

Rebuild with `npm run android` (5–20 min) only after a **native** change: a new library with
native code, `app.json` / config plugins, or a new Expo SDK. JavaScript changes and `.env` edits
need only a Metro restart. `android/` is generated by the build and gitignored; never edit it.

`EXPO_PUBLIC_SUPABASE_URL` holds this machine's LAN IP. If the router hands out a new one, update
`.env` and restart Metro.

### Troubleshooting

| Symptom                                                   | Cause and fix                                                                                                                        |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `adb: command not found`                                  | The terminal was opened before editing `~/.bashrc`: `source ~/.bashrc` or open a new one. Don't `apt install adb` (older, conflicts) |
| `adb devices` empty or `offline` over USB                 | USB hubs and docks often time out with `adb`. Plug in directly, or use wireless debugging                                            |
| `adb pair` → `protocol fault` or hangs at the code prompt | Used the connect port, or the pairing dialog closed. Reopen it and pair with the port it shows                                       |
| `INSTALL_FAILED_USER_RESTRICTED`                          | The install prompt on the phone timed out. `adb install -r android/app/build/outputs/apk/debug/app-debug.apk` and accept it quickly  |
| Metro gone after a failed `npm run android`               | Expo quits on install failure. `npm start`                                                                                           |
| Google sign-in fails with `DEVELOPER_ERROR`               | The Android OAuth client's package or SHA-1 doesn't match the build (see below)                                                      |
| Google sign-in works but Supabase rejects the token       | The local stack started without `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`: stop it and start it with `.env` exported                        |
| The app can't reach Supabase                              | Wrong LAN IP in `.env`, or a firewall blocking port 54321                                                                            |

## Google Sign-In (one-time setup)

The app signs in with Google through a native dialog and hands the ID token to Supabase. Three
things have to exist before the sign-in button works:

1. **Google Cloud OAuth clients** ([console](https://console.cloud.google.com/apis/credentials),
   any project; no billing). Create two clients:
   - **Web application**. Its client ID is `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` in `.env`; it is
     what issues the ID token.
   - **Android**, with package name `ar.tesolin.evenly` and the **SHA-1** of every keystore that
     signs the app. The dev build signs with the debug keystore Expo's template copies into
     `android/app/` on prebuild (not `~/.android/debug.keystore`). After the first
     `npm run android`, or `npx expo prebuild`:

     ```bash
     keytool -J-Duser.language=en -list -v -keystore android/app/debug.keystore -storepass android | grep SHA1
     ```

     With the SDK 58 template it is `5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25`
     (shared by every Expo project, which is fine for a dev build).

     The EAS build (T8) signs with the EAS-managed keystore: `npx eas-cli credentials` prints its
     SHA-1. Add it as a second fingerprint on the same Android client.

   Nothing from the Android client goes into the code: Google matches it by package and SHA-1.

2. **Supabase**: on the hosted project, Authentication → Sign In / Providers → Google → enable it
   and paste the **Web** client ID (and secret). The local stack already has the provider in
   `supabase/config.toml`; it takes the client ID from the environment, so export `.env` before
   starting it:

   ```bash
   set -a; . ./.env; set +a; npx supabase start
   ```

   The phone must reach the local API: put the machine's LAN IP in `EXPO_PUBLIC_SUPABASE_URL`
   (`http://192.168.x.x:54321`), not `127.0.0.1`.

3. `.env`: `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` and
   `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`. They are inlined at build time, so restart Metro after
   changing them.

The session is kept in `expo-secure-store` and survives restarts; the header menu signs out.
